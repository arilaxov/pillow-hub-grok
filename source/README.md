# Pillow Hub

Сайт Pillow, бесплатные инструменты, Enhanced Method и необязательный Telegram-бот. Node.js 18+, без npm-зависимостей для запуска.

Опубликованная копия для GitHub Pages — это содержимое `public/` в корне репозитория (подпуть `/pillow-hub-grok/`). Локальный сервер по-прежнему запускается из этой папки: `node server.js`. Страницы ссылаются относительно (`ai.html`, а не `/ai`), счётчик читает `api/config.json`, а ffmpeg.wasm — однопоточное ядро без COOP/COEP.

## Запуск

- macOS: открыть `Run Pillow Hub.command`.
- Windows: открыть `Run Pillow Hub.bat`.
- В терминале: `node server.js`, затем `http://127.0.0.1:8765`.

Открывать HTML двойным кликом через `file://` нельзя: браузеру нужен HTTP или HTTPS для запуска локального видеодвижка. Устанавливать FFmpeg на компьютер для работы сайта не нужно — WebAssembly-движок уже в `public/vendor/`.

При обновлении существующего проекта сохраните свой `.env` и папку `data/`. В поставке нет рабочего токена бота: новый `.env` при необходимости создаётся из `.env.example`. Для работы сайта, Method, Tools и скачивания расширения токен не требуется.

## Обработка видео

Файл не загружается на сервер. Быстрая упаковка и обработка средствами устройства работают в отдельном worker. Тяжёлый FFmpeg загружается только как запасной движок. После небольшого задания он остаётся готовым 30 секунд для повторного запуска; отмена и ошибка освобождают его немедленно. Большие задания освобождают память после завершения.

### Enhanced Method

1. Движок проверяет видеопоток, длительность, частоту кадров, звук и ориентацию, включая метаданные поворота.
2. Подходящий Full HD H.264/AAC-исходник упаковывается напрямую без перекодирования. Это сохраняет исходные кадры и ускоряет подготовку. Для других исходников используется кодирование средствами устройства; если оно недоступно, автоматически подключается FFmpeg. При перекодировании Pillow AI оценивает образец кадра и подбирает мягкие параметры.
3. Формируется настоящий Full HD H.264 SDR-файл: 1920 × 1080 для горизонтального видео или 1080 × 1920 для вертикального. Композиция не обрезается; несовпадающие пропорции дополняются полями. Частота до 60 FPS сохраняется, более высокая приводится к 60. AAC-аудио сохраняется, отсутствующая дорожка не добавляется.
4. Видео без повторного кодирования упаковывается в MPEG-TS и скачивается с именем `.mp4`. Именно такой тип упаковки описан у текущего 720p60 Method на CompressBase. Второй файл — обычный MP4 той же подготовленной картинки для плееров и редакторов. Предпросмотр использует обычный MP4.
5. Перед выдачей проверяются разрешение, длительность, наличие звука и контейнер. Запасной движок дополнительно декодирует короткий фрагмент. Повторное полное декодирование длинного ролика убрано ради скорости. Полное декодирование используется в независимых медиатестах.

Это самостоятельная реализация подготовки и упаковки, без API CompressBase и без копирования закрытого метода Editing News. Качество и подпись разрешения после публикации в TikTok определяются самой платформой. Изменение контейнера не даёт гарантии обхода её повторного кодирования. Пониженное качество исходника не превращается в дополнительную реальную детализацию только за счёт увеличения размера кадра.

### Что такое Pillow AI

Небольшой локальный нейронный классификатор `8 → 12 → 3`, используемый для выбора фильтров, а не для генерации кадров. Он обучен на 3600 собственных процедурных примерах гладких, детализированных и зашумлённых изображений; веса лежат в `public/assets/content-model.json`. Проверка при обучении использует отдельные синтетические примеры и не является показателем качества на произвольном видео.

Воспроизводимое обучение: `npm run train:model`. Ни ключ, ни облачный ИИ-сервис не требуются. Код признаков и вывода модели находится в `public/modules/content-analysis.mjs`.

### Max Quality

Метод максимального качества и максимального веса для заливки через TikTok Studio с компьютера (1080p-уровень TikTok).

1. **Мастер-файл.** Чистый H.264/AAC-исходник до 1080 по короткой стороне без поворота и с частотой до 60 FPS сохраняется как есть (без перекодирования, «encode once»). Остальное один раз кодируется в H.264 High: CRF 16 (FFmpeg) или VBR до 30 Мбит/с (кодировщик устройства), ключевой кадр каждые 2 с, BT.709, AAC 320 кбит/с 48 кГц при перекодировании звука. Размер уменьшается только до 1080 по короткой стороне, без полей и без увеличения. Более 60 FPS приводится к 60.
2. **Патч контейнера** (`public/modules/mp4-patch.mjs`, меняется только индекс `moov`, данные `mdat` побайтно те же): порядок `ftyp → moov → mdat`, бренд `isom`, `mvhd` переводится в версию 1 со всеми полями и длительностью `0xFFFFFFFFFFFFFFFF` («duration64»), минимальный блок метаданных (`©too`, `©cmt`), смещения чанков пересчитываются. Это актуальный на октябрь–ноябрь 2026 публичный вариант (CompressBase Variant 1 «duration64», buwryme `mvhd`). Предыдущий вариант с «призрачной» звуковой дорожкой (×10 сэмплов, edit list сохранён) реализован как профиль `ghost` для быстрого переключения.
3. **Проверка.** Перед выдачей перечитываются структура файла, версия и длительность `mvhd`, положение чанков; параметры видео и звука проверяются на непатченной копии.

TikTok часто меняет обработку: на 9–10 ноября 2026 CompressBase пишет, что их Quality + FPS временно не работает, бейдж buwryme — «patched out», OQM — «results can vary». Гарантии нет; проверять результат нужно по реально выданной TikTok копии.

### Tools

- **Pillow AI Enhancer:** только 2K (короткая сторона 1440) и 4K (2160) относительно исходника, пропорции сохраняются; размер, которого исходник уже достиг, отключается. Выход всегда H.265. Pillow AI сам подбирает силу шумоподавления, восстановления деталей, CRF и параметры x265 (`aq-mode=3`, `psy-rd`, `psy-rdoq`, deblock, SAO) по оценке шума и детализации, битрейту исходника, шагу увеличения и FPS. H.265 кодирует аппаратный энкодер устройства через WebCodecs (VBR, режим quality, contentHint detail) — Chrome/Edge на Windows и macOS, Safari. libx265 внутри ffmpeg.wasm зависает в браузере (проверено на однопоточном и многопоточном ядре 0.12), поэтому без HEVC-энкодера файл честно выдаётся в H.264 (x264 с `aq-mode=3` и `psy-rd`) с однострочной пометкой «No H.265 encoder on this device». Параметры x265 в плане сохраняются для будущего ядра. Это адаптивная обработка, а не генеративная модель уровня Topaz.
- **Auto Beats:** перетащите аудио или видео — маркеры находятся автоматически (трекинг долей + фиксированный порог по реальным ударам, плюс начала разделов). Волна с маркерами и кнопки: `.jsx` для After Effects (маркеры на выбранный слой или композицию, одно undo, повторный запуск заменяет маркеры Pillow), «Copy seconds» и маленькая кнопка JSON для панели (Music → Import from Pillow Hub).

### Pillow AI (v93)

- Страница `ai.html` (в меню — AI). WebLLM 0.2.88 грузится только на этой странице и только после кнопки Load; движок работает в Web Worker, интерфейс не подвисает.
- Модели: по умолчанию **Qwen3.5 2B** (q4f16, ~1,1 ГБ скачивания, ~2,2 ГБ видеопамяти; хорошо знает русский и английский), запасная **Lite — Qwen3.5 0.8B** (~0,45 ГБ, ~1,6 ГБ видеопамяти). Без `shader-f16` берутся q4f32-сборки. Скачивается один раз с Hugging Face и хранится в Cache Storage браузера; прогресс показывается в процентах и мегабайтах.
- Нужен WebGPU: свежий Chrome/Edge или Safari, лучше всего Mac на Apple Silicon. Открывайте через `http://127.0.0.1:…` или HTTPS — по http на IP в локальной сети браузер WebGPU не даёт. Без WebGPU страница честно пишет об этом и отвечает по справочнику; инструменты в чате всё равно работают.
- «Обучение»: системный промпт (кто такой Pillow AI, авторы ARILAX & KABAN, каналы, бот) + локальный RAG: `public/assets/pillow-ai-knowledge.json` (BM25 по-русски и по-английски, 3 лучших фрагмента в каждый запрос). Чтобы научить новому — добавьте запись `{id, title, tags, text}` в этот файл.
- Действия: перетащите видео или аудио в чат и напишите, что нужно («макс качество для тиктока», «апскейл в 4K», «найди биты и дай jsx»). Намерение определяется правилами (RU/EN); если неясно — модель отвечает JSON `{"action": …}`; если и так неясно — чат предлагает кнопки. Запускаются те же модули, что на сайте (video-engine, mp4-patch, beat-analysis, ae-bridge), результат — карточка с загрузками.

### Мост с After Effects

`public/modules/ae-bridge.mjs` — ES3-рантайм для ExtendScript и генераторы `.jsx`/JSON (`pillow.beats.v1`). Тот же рантайм встроен в `host/pillow.jsx` панели. `npm run build:panel` пересобирает `public/downloads/Pillow-v192.zip` (имя и структура прежние, версия панели 1.1.1): кнопка «Import from Pillow Hub» в Music принимает JSON с маркерами. После пересборки обновите хеш и размер в `extension.html`.

Лимиты видео: 256 MB, до 10 минут, исходник до 4K SDR. HDR нужно предварительно экспортировать в SDR, чтобы не получить неверные цвета. Время и доступная память зависят от устройства. Это офлайн-кодирование внутри браузера, поэтому длинное видео может обрабатываться долго.

## Telegram и API панели

Бот необязателен: `/start`, `/app`, `/extension`, `/tools`, `/method`, `/status`. Команда `/extension` и ссылка `?start=get` отдают ZIP напрямую. Для Mini App задайте публичный HTTPS-адрес в `PUBLIC_URL`. Администраторские права в каналах больше не требуются.

- `GET /api/config` — настройки и счётчик скачиваний.
- `GET /version` — версия для проверки обновлений After Effects-панели.
- `POST /feedback` — отзывы панели в `FEEDBACK_CHAT_ID`, если задан бот.
- Необязательные подписанные Telegram-входы сохранены для совместимости; инструменты от них не зависят.

При смене ZIP расширения обновите `EXT_FILE` в `.env` и имя файла в `extension.html`.

## Проверки

`npm test` — юнит-проверки (`npm run test:units`: Auto Beats, генераторы `.jsx`/JSON в модели AE с ES3-проверкой, импорт в панель, размеры и автоподбор Enhancer, план Max Quality, патч MP4 с проверкой через FFmpeg/FFprobe) и интеграционные проверки сервера с локальным Telegram-моком: свободное скачивание, статика и WASM, приватные файлы, входы, Mini App, команды бота и API панели. Тест использует временную базу и не удаляет реальные данные.

Полная проверка интерфейса и готовых видео:

```sh
npm install --no-save playwright
npx playwright install chromium
npm run test:browser
```

Для этой дополнительной проверки нужны FFmpeg и FFprobe в PATH: они создают синтетические ролики и независимо проверяют скачанный результат. Тест проверяет Pillow AI (режим без WebGPU, мок-движок WebLLM, действия из чата), Enhanced, Max Quality (структура патча, побайтное сохранение потоков), Enhancer 2K/4K (H.265 или объявленный H.264-фолбэк), Auto Beats, звук, портретную ориентацию, 60/120 FPS, поворот, шумоподавление, ошибки файлов, отмену и повторный запуск, скачивание, мобильную вёрстку и отсутствие внешних запросов. Реальный бот и пользовательские видео не используются. `CHROMIUM_PATH` позволяет задать свой Chromium, `SCREENSHOT_DIR` — папку снимков.

## Изученные источники

Pillow AI (проверено 10 ноября 2026): npm `@mlc-ai/web-llm` 0.2.88 (вышел 10.11.2026), список prebuilt-моделей в его `lib/index.js` (Qwen3.5 0.8B/2B/4B/9B, Qwen3, Llama 3.2, Phi-4 mini, Gemma 2, SmolLM2), размеры весов — Hugging Face API `mlc-ai/Qwen3.5-*-q4f16_1-MLC` (2B ≈ 1083 МБ, 0.8B ≈ 447 МБ, 4B ≈ 2390 МБ).

Max Quality (проверено 10 ноября 2026):
- https://compressbase.com/method-api — Variant 1 «Experimental (recommended), duration64 without ghost samples or an appended marker», Variant 2/3 — ghost-сэмплы; лимит 1080p; баннер «Quality + FPS temporarily down».
- https://github.com/buwryme/tiktok-lossless-upload (MIT) — коммит 23.10.2026 «add mvhd header patch method», метод по умолчанию `mvhd`; статус-бейдж «patched out...».
- https://github.com/naveen-gunawardana/open-upload-method (MIT) — OQM: каталог патчей, исправление edit list у клона, рецепт мастера (CRF 17, AAC 320k); 05–06.11.2026 «results can vary».
- https://github.com/BastienGimbert/tiktok-quality (MIT), https://github.com/irgifebry/NoBlur — ghost-кадры / раздувание таблиц сэмплов (более ранний вариант).
- https://github.com/AscendedTweaks/silent-method (08.11.2026) — MPEG-TS в `.mp4` даёт 720p60 (тот же принцип, что Enhanced).
- https://www.reddit.com/r/upscaling/comments/1w4b15i/ — отзыв пользователя: «первый» метод CompressBase сохраняет максимум качества, но фиксирует один уровень 1080p; слишком высокий битрейт мешает стримингу.

Лицензии и благодарности — `THIRD-PARTY.md`.

Enhanced:

- https://compressbase.com/upload-method — описание 720p60 после выбора тестового видео: MPEG-TS с расширением `.mp4`, без перекодирования на этапе упаковки.

## Сторонняя медиабиблиотека

Быстрая работа с контейнерами и WebCodecs использует неизменённый Mediabunny 1.45.0 (MPL-2.0). Лицензия и ссылка на соответствующие исходники находятся в `public/vendor/mediabunny/`. Все файлы поставляются с сайта; пользовательские видео не отправляются внешним сервисам.
